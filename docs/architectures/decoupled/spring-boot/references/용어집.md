# 용어집

본 문서는 Spring Boot 표준 문서 전반이 쓰는 용어의 뜻을 정의합니다. 같은 낱말을 문서마다 다르게 쓰지 않기 위한 기준입니다.

| 용어 | 정의 | 참고 출처 |
| :--- | :--- | :--- |
| **모듈러 모놀리스** | 단일 배포 산출물을 유지하되 내부 모듈의 경계와 결합도를 엄격히 관리하는 아키텍처 스타일 | [Kamil Grzybek](https://www.kamilgrzybek.com/blog/posts/modular-monolith-primer) |
| **바운디드 컨텍스트** | 특정한 도메인 용어 체계와 모델이 일관되게 적용되는 경계 | [Martin Fowler](https://martinfowler.com/bliki/BoundedContext.html) |
| **애그리거트** | 데이터 변경의 단위로 다루어지는 연관 도메인 객체의 묶음 | [Martin Fowler](https://martinfowler.com/bliki/DDD_Aggregate.html) |
| **CQRS** | 명령과 조회의 역할 및 데이터 접근 경로를 분리하는 패턴 | [Martin Fowler](https://martinfowler.com/bliki/CQRS.html) |
| **상류 · 하류** | 계약을 정하고 공급하는 쪽과 그것을 수용해 자기 업무를 수행하는 쪽 | Eric Evans, *DDD Reference* |
| **공개 계약 (OHS)** | 상류가 모든 소비자에게 하나로 공개하는 인터페이스. 소비자별 협상을 대신합니다 | Eric Evans, *DDD Reference* |
| **공개 언어 (PL)** | 공개 계약이 주고받는 별도 타입 집합. 내부 모델의 변경을 하류로 번지지 않게 합니다 | Eric Evans, *DDD Reference* |
| **부패 방지 계층 (ACL)** | 상류 모델의 변경이 자기 도메인에 미치는 영향을 차단하는 번역 계층 | Eric Evans, *DDD Reference* |
| **순응 (Conformist)** | 상류 타입을 번역 없이 그대로 쓰는 수용 방식 | Eric Evans, *DDD Reference* |
| **포트 · 어댑터** | 핵심 도메인이 기술 세부와 분리되도록 입출력 지점을 인터페이스로 두는 구조 | [Alistair Cockburn](https://alistair.cockburn.us/hexagonal-architecture) |
| **의존 역전** | 상위 모듈이 하위 모듈의 구현이 아니라 추상화에 의존하게 하는 원칙 | [Wikipedia](https://en.wikipedia.org/wiki/Dependency_inversion_principle) |
| **피쳐** | 컨텍스트의 `application` 아래 유스케이스 단위 패키지. 컨트롤러부터 포트까지 한자리에 모입니다 | |
| **조회 포트** | 피쳐가 소유하는 인터페이스. 화면 DTO를 직접 반환하며 어댑터가 SQL을 갖습니다 | |
| **재구성** | 저장된 값으로 도메인 엔티티를 되살리는 경로. 저장소만 호출하며 불변식 검증을 거치지 않습니다 | |
| **통로 안티패턴** | 계층을 통과하되 아무 로직 없이 전달만 하는 형태. 화면 조회에 한해 허용합니다 | |
